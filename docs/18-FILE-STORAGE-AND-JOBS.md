# Private Files, Outbox and Background Jobs

## Storage contract

Implementation refinement: [ADR-013](../adr/ADR-013-phase2-bounded-local-content.md) supplies private mounted storage and bounded synchronous imports/exports for local Phase 2. The S3/distributed job contract below remains the target for evidence/report and public-pilot phases.

Domain sees FileObject IDs; adapter supports put/get/delete/head using opaque keys. Development uses an S3-compatible local service; production uses compatible private object storage. Files never become public merely because a URL is guessable. Runtime credentials have least-privilege bucket/prefix access; bucket encryption and backups are deployment responsibilities.

File lifecycle: allocated→uploading→validating→ready/rejected→expired/deleted. Authorize both upload initiation and final parent binding. A file uploaded for a logo cannot be rebound as another learner's evidence; purpose and ownership are immutable. Server computes hash and checks actual bytes; client MIME/size are hints only.

Initial policies: logos PNG/JPEG/WebP <=2 MiB; evidence images <=5 MiB, PDF <=10 MiB, UTF-8 TXT/MD <=2 MiB; per attempt <=10 attachments and 25 MiB total. SVG/HTML/executables/office macros are unsupported. Import policies are defined in the Markdown spec. Original names are display-only sanitized strings; keys use workspace UUID+random file UUID, never user path traversal input.

Downloads go through current authorization proxy with no-store. This preserves next-request revocation; future signed URLs would need an explicit expiry-window tradeoff ADR. Evidence lookup follows authorized attempt/enrollment binding. Report blob uses ReportSnapshot binding. Import raw source is readable only by authorized requester/creator and owner per content permissions, never through general learner access.

## Reliable job intent

Email delivery captures recipient locale at scheduling: saved user preference when available, otherwise workspace default locale for invitations. Authentication emails use the verified intended account/pre-login preference through the auth callback. Templates are fully translated fa/en. Notification records keep stable message keys/arguments so UI renders the recipient's current locale. PDF jobs use frozen ReportSnapshot locale, never worker-machine locale.

Domain transaction writes both factual change and OutboxEvent. Dispatcher reads undispatched events under bounded lock, enqueues pg-boss job with event/dedupe key, then marks dispatched. Crash may requeue the same event; handler/database constraints prevent duplicate domain effects. External email may still duplicate after ambiguous provider acceptance; document that and prefer provider idempotency keys.

| Job | Input | Idempotent result |
| --- | --- | --- |
| import.parse | ImportRun ID, requester/workspace | One schema-valid proposal and warnings |
| import.ai | ImportRun ID, disclosed/configured provider | One bounded validated proposal; no publication |
| report.pdf | ReportSnapshot ID | One ready private PDF binding for fixed model hash |
| path.export | Version ID, export JobRun | One private artifact for selected immutable content |
| progress.export | Enrollment/requester | Scoped JSON snapshot at fixed cutoff |
| email.deliver | Outbox event ID/template/recipient ref | Delivery receipt/dedupe key, secret token fetched securely |
| cleanup | Scoped expiration batch | Delete only expired unbound/retention-approved objects |

Do not store raw invitation/reset token in general Outbox payload. Auth emails use provider-integrated callback or encrypted short-lived delivery payload with separate key and deletion after delivery; hash-only invite storage is not enough to resend an existing secret. Reissue generates a new token/invite rather than reconstructing it. This distinction must be verified in Foundation.

## State, retry and access

JobRun: queued→running→succeeded/failed/cancelled. Lease/heartbeat detects abandoned workers. Bounded exponential retry for transient storage/email/PDF errors, max 3 attempts; AI max two calls including repair. Validation/permission/revocation failures are terminal. User retry creates new intentional attempt or requeues the same failed artifact with same factual identity as appropriate, never repeats approved transitions.

Revalidate requester membership/capability at execution and before publishing result. Notifications generated by already committed domain events may deliver to currently active intended recipients even if originating actor is removed; direct user-requested exports/AI jobs fail on requester revocation. Keep the distinction explicit in job policy.

## Orphans and rendering isolation

Do not delete an object referenced by immutable submitted evidence/report/version assets. Upload intents unbound after 24h expire; failed outputs after 7d clean up; raw imports follow 30d default. Cleanup checks DB bindings, not filenames alone. Bucket inventory reconciliation detects missing/redundant objects and alerts rather than automatically erasing history.

PDF worker has a capped Chromium process pool, bundled Unicode/RTL fonts, memory/time limits and blocked outbound network. It renders controlled data/HTML locally. Job logs contain IDs, timing, safe error class and counts, not source/evidence/note bodies.

Back up database and objects coherently. Restore rehearsal checks that referenced accepted files are retrievable and restored pending jobs do not duplicate domain records. Exact schedules/object provider are finalized at deployment gate.
